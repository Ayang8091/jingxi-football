竞彩足球预测数据源调研与接入方案

竞析 JINGXI · 2026-09-29 · 目标：筛选准确率较高且稳定的公开预测接口，接入后用真实赛果回测持续优化

一、结论先行（TL;DR）

  • 立即接入（免费、零成本起步）：① API-Football 免费层（100 次/天，覆盖全玩法预测，含中场/阵容特征）＋ ② boggio Football Prediction API 免费层（50 次/天，自带「近 1/7/14/30 天命中率」官方统计端点，是唯一开箱即有准确率口碑背书的源）。
  • 必做基线：官方竞彩 SP 隐含概率（1/SP 去水）——它是市场共识，任何外部源先跟它比，跑不赢 SP 就没有接入价值（文献结论：没有公开模型能长期稳定跑赢收盘赔率）。
  • 国内源：雷速/球探等官方数据服务均需商务合作（无自助 API）；市面「99 元/月」类站点多为第三方转售，稳定性与合规存疑，不建议主力依赖。竞彩玩法本身以体彩官方接口为准（已在用）。
  • 已落地：接入层 tools/predict-providers.js（4 个 Provider + 重试 + 缓存 + 密钥管理）与回测 tools/backtest-providers.js（命中率 / Brier / LogLoss / ROI），37 项测试全绿，今日真实数据已验证（8 场）。
  • 现实预期：胜平负 Top-1 命中率的市场公平水平约 52%~55%（平衡测试集）；命中率提升的主要空间在概率校准（Brier/LogLoss）与价值筛选（EV>0 的场次），而不是盲目追高 Top-1。

三、接入方案（已实现）

1. 架构：统一 Provider 适配层

tools/predict-providers.js          ← 接入层（本次新增）
  ├─ PROVIDERS.sportterySP          官方 SP devig 基线（离线可跑，无密钥）
  ├─ PROVIDERS.apiFootball          GET /v3/predictions?date=   (x-apisports-key)
  ├─ PROVIDERS.footballPrediction   GET /api/v2/predictions     (X-RapidAPI-Key)
  ├─ PROVIDERS.apifyForebet         Apify Actor run-sync        (token)

3. 请求封装 / 解析 / 重试 / 缓存

机制实现
请求封装fetchWithRetry()：15s 超时（AbortController）、可注入 fetchImpl
异常重试429/5xx 指数退避（1s→2s→4s，上限 30s，默认 3 次）；4xx 直接抛错不重试
数据解析各 Provider 独立 parse()，非 JSON / 缺字段容错（产出 0 条而不炸）；概率统一归一化（和=1）；无概率时用赔率反推（1/SP）
缓存api/cache/predictions/<provider>/<date>.json，TTL 6 小时，--no-cache 可绕过；运行时缓存不入库
跨源对齐队名归一化（去 FC/AC 前后缀、常见别名映射）+ 双别名 key（官方场次号优先、归一化队名兜底）

四、适用场景与局限

源适用场景局限
API-Football每日批量拉取预测做「第二意见」；免费额度足够 8~15 场/天免费层 100 次/天封顶；预测为通用共识，对竞彩冷门联赛（女足/青年赛）覆盖弱；队名需映射
Football Prediction API持续跟踪一个有公开准确率背书的模型；其 performance-stats 可当第三方 benchmark50 次/天只能查 1~2 天；联赛覆盖少于 API-Football；市场 classic=1X2，无让球/总进球概率明细（部分玩法只有 yes/no）
Forebet（Apify）需要精确比分/大小球/亚洲盘多玩法参考时；历史预测页可回溯补历史非官方 API，页面改版即断；按量计费但量小成本低；概率口径为其自有模型，校准度需自行回测
sportterySP 基线一切对比的锚点；也是「无外部源」时的下限保障隐含概率含抽水（devig 只能去除大部分）；只反映市场定价，不含基本面信息
国内转售 API—合规与稳定性风险，不建议生产依赖
关键提醒：竞彩玩法中「胜平负」以外的玩法（总进球/比分/半全场）公开预测源覆盖很弱，外部源主要提升的是 1X2 方向与进球数预期；竞彩特有的让球盘仍要靠官方 SP + 站内模型。

五、命中率评估方法（已实现，可持续运行）

1. 指标口径

指标公式解读瞎猜基线
Top-1 命中率pick == 实际赛果 的比例直观；但平局少的联赛会虚高≈33%（均衡时）
多分类 Brier ↓Σ(预测概率 − 实际01向量)² / n考察概率校准，比命中率更科学≈0.667
LogLoss ↓−ln(实际方向的预测概率) 均值惩罚「自信地错」≈1.099
ROI（官方 SP）按 pick 买入，中了拿 SP、没中损 1 注的均值最终标准：命中率高低不重要，能不能赢抽水才重要−100%×抽水率（竞彩约 −18% 前提下需 55%+ 命中高 SP 才打平）

2. 回测流程（每赛后运行）

① 收预测：node tools/predict-providers.js --date <开赛日>   （写入 api/cache/predictions/）
② 填赛果：官方 App/网页核对后填 tools/fixtures/backtest-results.json（或逐日文件）
   { "date":"2026-09-29", "matchNum":"周二008", "home":"苏格兰", "away":"瑞士",
     "result":"a", "sp":{ "h":4.22, "d":3.36, "a":1.68 } }
③ 跑回测：node tools/backtest-providers.js --results <结果文件>
④ 决策：连续 ≥100 场样本上，命中率与 Brier 同时跑赢 sportterySP 基线的源才保留；
   两个源概率接近时用逆方差加权/简单平均融合，融合后重新回测。

3. 持续优化闭环

  • 样本量纪律：单日 8~15 场波动极大，评估窗口至少 100~200 场；先看 Brier 再看 ROI。
  • 融合优于二选一：把各源概率与 SP 隐含概率做加权平均（权重 = 各自回测 Brier 的倒数），通常优于任何单一源。
  • 价值筛选：只在外部源概率 × 官方 SP > 1（EV>0）的场次上提高置信度输出，这是把「预测准」变成「有价值」的唯一路径。
  • 后续可加：① 赛果自动抓取（换网络环境或经 CORS 中继绕 WAF）；② 预测写入「今日预测」页做外部参考列；③ 命中率走势页展示。
